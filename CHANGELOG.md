# Changelog

All notable changes to this project are documented here.

## [Unreleased]

## [1.0.0] - 2026-10-28

The first stable release. The public Kotlin API, the Portable Bridge ABI, and
the result schema are frozen under semantic versioning: additive changes ship in
a minor release, and any breaking change waits for 2.0.0 or an ADR that
supersedes the current contract.

### Added

- Stable public API covering every feature sherpa-onnx exposes through the
  bridge: offline ASR, streaming ASR, VAD, TTS, keyword spotting, punctuation,
  speaker diarization, and speech enhancement.
- Semantic-versioning commitment documented in
  [`docs/versioning.md`](docs/versioning.md), including the compatibility rules
  for the Kotlin API, the bridge ABI, and the sherpa-onnx core range.
- Platform capability matrix recording what each target family ships
  ([`docs/platform-matrix.md`](docs/platform-matrix.md)).
- Migration guide for 0.4.0 and earlier consumers
  ([`docs/migration-1.0.md`](docs/migration-1.0.md)).
- Web bridge now builds with TTS and speaker diarization enabled, so the browser
  advertises the same ten resources as the native transports.
  `scripts/check-web-capabilities.cjs` loads the built module and fails the
  build if a resource is missing from its capability report.

### Fixed

- `armeabi-v7a`, `x86`, and `x86_64` Android bridges now link. Android below API
  29 exports no TLS helper from `libc`, and enabling TTS was what first
  referenced the upstream `thread_local` in `normal-data-generator.cc`.
  `patches/0002` removes the TLS reference entirely by moving the RNG holder to
  an instance member, instead of carrying an emulated-TLS flag through every
  Android build. `scripts/check-android-aar.sh` now asserts that no bridge
  imports a TLS helper on any ABI, so a future upstream bump that reintroduces
  one fails the release rather than the device.
- `scripts/package-jvm-native.sh` emits the versioned
  `sherpa-onnx-kmp-jvm-native-<platform>-<version>.jar` name and ships only the
  runtime libraries, not the static archives that tripled the download.
- `scripts/package-apple-xcframework.sh` no longer overwrites the release
  `SHA256SUMS`, so the manifest generated by `package-release.sh` covers the
  whole artifact set.

### Changed

- The Apple preview gates on the physical-device evidence recorded in
  [`docs/status.md`](docs/status.md); iOS and macOS are no longer described as
  preview targets.
- `sherpa-onnx` core is pinned to `v2.0.1`; the supported range and the ABI
  binding are published in [`docs/bridge-abi.md`](docs/bridge-abi.md).

### Verification

- 45 JVM tests, 36 JS Node tests, 36 JS browser tests, 42 macOS arm64 tests, and
  42 iOS Simulator arm64 tests pass.
- Android device suite passes on an API 36.1 arm64 emulator.
- Eight real-model feature suites pass on the JVM, macOS arm64, and the iOS
  Simulator: VAD, KWS, punctuation, speech enhancement, streaming transducer
  ASR, speaker diarization, lexicon TTS, and phoneme-codepoint TTS.
- Bridge C ABI probe covers 10 resources and 35 operations, including a real
  TTS synthesis and audio pull.
- Release hardening verifies header/library ABI agreement, dependency paths,
  and bounded native memory growth over repeated create/destroy.
- The pinned model transcribes in Chrome through the real worker path.

## [0.9.0] - 2026-10-28

### Added

- `scripts/check-release-hardening.sh`: header/library ABI agreement, release
  dependency audit (no builder paths), and a repeated create/synthesize/destroy
  memory-growth check that bounds growth per iteration and in total.
- `scripts/benchmark-release.sh`: writes a versioned JSON snapshot with cold
  start, core version, ONNX Runtime version, host, and the audio checksum.
- `scripts/check-android-aar.sh` now inspects the packaged
  `libsherpa-onnx-portable-bridge.so` in every ABI for the eight bridge entry
  points, so a stale AAR from an earlier feature set cannot ship.

### Verification

- The memory check measures peak RSS in a fresh process per data point and
  compares two warm points deep enough into the run that ONNX Runtime's arena has
  reached its plateau. Measured on the development host: 32→128 iterations grew
  327 KB per iteration, 128→384 grew 158 KB per iteration, and 512→1024 shrank
  34 MB. The falling-then-negative rate is arena reuse, not a leak; comparing one
  iteration against many would report the arena itself as growth.
- `ru_maxrss` is normalized to KiB. It is bytes on macOS and kilobytes on
  Linux, and treating it as one unit inflated growth by 1024x on macOS.

### Fixed

- Android native compilation could not find `onnxruntime_cxx_api.h`: the Android
  ONNX Runtime archive unpacks headers into `headers/`, not `include/`. The
  CMake lookup now accepts both.

## [0.8.0] - 2026-10-28

### Added

- Offline TTS with `Flow<AudioChunk>` delivery, `sampleRate` and `numSpeakers`
  discovery, and per-chunk progress metadata.
- `TtsRequest.phonemeCodepoints` for Piper VITS models. sherpa-onnx v2.0 removed
  the built-in espeak-ng, so a Piper model without a lexicon needs Unicode
  codepoints supplied by the caller; lexicon models such as
  `vits-icefall-zh-aishell3` run from plain text.
- Keyword spotting with `KeywordSpotter` and `KeywordSpotterStream`, including
  per-stream keyword overrides.
- CT-Transformer punctuation restoration.
- Speaker diarization over pyannote segmentation plus a speaker-embedding model.
- GTCRN speech enhancement.
- Typed configs, shared option mappers, and shared result mappers for all five
  new features in `commonMain`.

### Verification

- Eight real-model integration suites pass on the JVM, macOS arm64, and the iOS
  Simulator.
- The bridge ABI probe advertises 10 resources and 35 operations.

### Fixed

- Piper TTS produced silence with raw text: the bridge now forwards
  `phoneme_codepoints` and reports a clear error when a Piper model needs them.
- Diarization segments legitimately overlap across speaker changes by up to the
  segmentation window, so the ordering assertion allows a one-second overlap
  instead of demanding strict monotonicity.

## [0.7.0] - 2026-10-28

### Added

- Streaming ASR: `OnlineRecognizer`, `OnlineSession.push`, `finish`, `reset`,
  and `result`, with endpoint detection and per-stream hotwords.
- Voice activity detection: `acceptWaveform` returns every completed segment,
  `flush` drains the tail, and `isSpeechDetected` exposes the detector state.
- Bridge ABI v2, adding `SherpaOnnxBridgePushAudio` and
  `SherpaOnnxBridgePullAudio` for streaming input and generated-audio output.
- Flow-based event delivery for chunked output.

### Verification

- Chunked and non-chunked input produce equivalent transcripts.
- Session close while work is active neither leaks nor crashes.
- The web worker batches streaming operations instead of issuing one round trip
  per frame.

## [0.6.0] - 2026-10-28

### Added

- Kotlin/JS web target with `WebWorkerTransport`, a dedicated worker, and the
  Emscripten sherpa-onnx build inside it.
- Transferable `Float32Array` audio transfer across the worker boundary.
- `HttpModelStore` and `MemoryModelStore` for browser model loading.
- `scripts/test-web-browser.sh`: a Playwright e2e run that fails unless the
  pinned model returns a non-empty transcript through the worker.

### Fixed

- JS strings were passed to `const char *` parameters without heap conversion.
- The Emscripten build did not export the runtime helpers the worker needs.
- The Wasm module used Emscripten's 64 KiB default stack and a split 64-bit ABI,
  which aborted under real inference.

## [0.5.0] - 2026-10-28

### Added

- Linux x64/arm64 and Windows x64 `mingwX64` native desktop transports.
- Shared `NativePortableTransport` in `nativeMain`, replacing the Apple-only
  transport. Apple, Linux, and Windows now use one cinterop implementation.
- `FileModelStore` and `createSherpaRuntime()` for Linux and Windows.
- `build-native-desktop.sh` producing an aggregate static archive on Linux and
  a bridge DLL on Windows.
- `platform-native` CI building and testing all three desktop targets on native
  runners, with runtime dependency inspection.
- ADR 0007 recording the Linux static / Windows dynamic linking decision.

### Verification

- `linuxX64`, `linuxArm64`, and `mingwX64` compile and link.
- Apple, JVM, and JS targets still compile and pass their tests.
- The desktop contract suite runs without the pinned model and performs real
  inference when `SHERPA_ONNX_KMP_TEST_MODEL_DIR` is set.

### Known limitations

- `linuxArm64` requires an aarch64 build host.
- Desktop real-model inference runs in CI on native runners, not on the
  development host.

## [0.4.0] - 2026-10-28

### Added

- Kotlin/Native cinterop transport for the Portable Bridge.
- Apple targets for iOS device, iOS Simulator, and Apple Silicon macOS.
- `FileModelStore` and `BundleModelStore` for Apple.
- Self-contained `SherpaOnnxKmp.xcframework` with the bridge, sherpa-onnx,
  and ONNX Runtime statically embedded.
- SwiftUI iOS sample and Swift macOS command-line sample.
- Apple CI covering native builds, cinterop, real-model inference, simulator
  execution, XCFramework creation, code signing, and device linking.
- `@Throws` annotations on asynchronous public APIs so Swift receives Kotlin
  failures as `NSError` instead of terminating the process.

### Verification

- macOS arm64 and iOS Simulator transcribe the pinned Persian ASR model.
- The iOS device framework and sample app link without a connected device.
- XCFramework slices contain exactly one bridge and one ONNX Runtime symbol.
- No external ONNX Runtime framework is referenced by the XCFramework.
- The sample app installs, launches, and transcribes in iOS Simulator.

### Known release gate

- A physical iPhone execution test was not available on the development host.
  Device compilation and linking pass, but Apple support remains preview until
  that test is recorded.
